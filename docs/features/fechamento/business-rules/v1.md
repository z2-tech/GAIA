## 1. What the feature is

During a project the user makes as many calculations as they want in every plot (talhão) and module: Emissão (emissions, through LCA, life cycle assessment), Remoção (soil carbon removal, through the RothC model), Regenerativo (regenerative practices score) and Biodiversidade (biodiversity). Each module has one official calculation per plot and season; the others are simulations.

When the work is done, Peterson and the client finalize the project. The platform shows one number per indicator for each farm and for the project, a weighted mean of the official calculations of the plots. Finalizing locks the official calculations and keeps a snapshot of that moment.

A client who wants to make a claim (communicate the result) then sends the project to third party verification, for example by Control Union. The auditor either sends it back for corrections or approves it, and a verified project never changes again. Export, PDF, QR code and auditor all read the official calculations.

## 2. Why

- Nothing says which calculation is real; a test and the real one look the same, so a buyer may get a number built on a simulation
- A number already given to a client can change: recalculation overwrites it, and factors and weights change under it
- There is no farm or project number, and the client needs a single number per indicator
- "Completed" is set by the platform at 100% and undone on any change, so it cannot mean "declared"

## 3. Vocabulary

| Term | Meaning |
|---|---|
| **Cálculo** | Any assessment in any module, for one plot (or a whole farm registered as one plot) |
| **Oficial** | The calculation that represents the real situation of a plot, module and season. Screen name |
| **Simulação** | Any calculation that is not official. Screen name |
| **Linha de base** | The first data collection of a project, "a foto de onde começamos" [R1 Q1 Paulo] |
| **Monitoramento** | Every collection after the baseline [R1 J1 Paulo] |
| **Safra** | The agricultural season, the period of an official calculation [R1 Q7] |
| **Finalizar** | The explicit action that closes the project's official calculations |
| **Foto** | The snapshot kept at finalize: inputs, results and factors of each official calculation |
| **Claim** | A company's public communication of a result [R1 J1 Paulo] |
| **Verificado** | State of a project an auditor approved; it never changes again |

"Cenário BAU" (business as usual) and "cenário de projeto" stay Remoção terms, the two runs of the soil model; they are not names for official and simulation [R1 Q3 Paulo].

## 4. Journey

1. Peterson closes a project with a client and gives access to whoever collects data [R1 J1 Ruan].
2. A Peterson technician, sometimes the client's or the farm's own people, collects the baseline and fills it in the platform; collection and filling are usually one step [R1 J1 Paulo, R1 J2 Ruan].
3. On top of the real data they simulate practices to find better management; later collections (monitoring) work the same way [R1 J1 Paulo].
4. The project admin or manager marks the official calculation of each plot, module and season.
5. Peterson and the client decide the project is done. A project admin or manager reviews the official calculations in a confirmation step and finalizes [R1 J3, R1 Q15].
6. The official calculations lock and the platform keeps the snapshot (P-1).
7. A client making a claim sends the project to verification. The auditor reads everything and changes nothing [R1 Q4 Paulo, Ruan].
8. If the auditor asks for corrections, the project reopens for Peterson and the client, who fix and resubmit; when the auditor approves, the project is verified and stays locked for good [R1 Q4 Paulo, R1 J6].
9. The client receives the results: PDF, platform access, QR code on the product or lot, report, spreadsheet [R1 J7].

## 5. Business rules

### 5.1 Official and simulation

- RN-01 Every module (Emissão, Remoção, Regenerativo, Biodiversidade) has an official calculation; every other calculation is a simulation. [2026-09-29 39:24] [R1 Q10 Paulo, Ruan]
- RN-02 There is one official calculation per plot, module and season; when a plot has two crops in one year, each crop has its own. [R1 Q6 Ruan] [R1 Q8 Paulo, Ruan] (P-13)
- RN-03 The season (safra agrícola) is the period of an official calculation. [R1 Q7 Paulo, Ruan] (P-6)
- RN-04 Any calculation, a simulation included, can be marked official. [R1 Q2 Paulo, Ruan] (P-10)
- RN-05 While a project is in progress, users create, change and delete calculations freely and can change which one is official. [2026-09-29 40:56] [R1 Q12 Ruan] (P-1)
- RN-06 When a plot has a single calculation for a module and season, it is official by itself. [R1 Q27 Paulo, Ruan]
- RN-07 When the official calculation is deleted, the platform asks the user to choose another; it never picks one by itself. [R1 Q28 Ruan, default]
- RN-08 The screen names are "Oficial" and "Simulação". [R1 Q3, default]
- RN-09 Data sent from the mobile app counts like data entered on the web and can be official. [R1 Q30 Paulo] (P-7)
- RN-10 In projects that already exist, the newest calculation of each plot, module and season becomes official, and the user is asked to review. [R1 Q29 Ruan, default]

### 5.2 The declared number

- RN-11 What is declared is the real data of that moment, never a simulation that was not made official. [2026-09-29 39:44] [R1 J1 Paulo]
- RN-12 Each indicator has a single declared number (carbon footprint, Regenerativo score, soil carbon removal, Biodiversidade), a weighted mean of the official calculations of the plots. [R1 Q1 Paulo] [R1 Q27 Paulo] [2026-09-29 38:16] (P-11)
- RN-13 The declared number exists per farm and per project, and the plot values stay visible for a client who reports by plot. [R1 Q11 Paulo, Ruan]
- RN-14 For Remoção, the declared number is the stock change over the season, in t CO2 per hectare; the projection is extra information, never the declared number. [R1 Q9 Paulo] (P-4)
- RN-15 Farm and project dashboards use only official calculations. [R1 Q24 Ruan, Paulo]
- RN-16 Comparison shows simulations only when the user asks for them. [R1 Q25 Ruan, default]
- RN-17 Benchmarks (reference means) ignore simulations. [R1 Q26 Ruan, default]

### 5.3 Finalizing and locking

- RN-18 Finalizing is an explicit action; reaching 100% completeness never finalizes a project. [R1 Q13 Ruan, Paulo] (`gaia-api/projects/services.py:78-91` does it automatically today)
- RN-19 Before finalizing, the user goes through a confirmation step that shows the official calculation of each plot, module and season. [R1 J3 Ruan]
- RN-20 A plot with no official calculation blocks the finalization. [R1 Q14 Ruan] (P-8)
- RN-21 Finalizing locks the official calculations: neither Peterson nor the client can change their data. [R1 Q12 Ruan] [R1 J5 Paulo] [R1 Q4 Paulo] (P-1)
- RN-22 At finalize the platform keeps a snapshot of each official calculation: its inputs, its results and the factors it used. [2026-09-29 39:44, 41:12]
- RN-23 A new emission factor never changes a finalized number. [R1 Q19 Paulo] (P-5)
- RN-24 After finalizing, the project's calculations can be viewed, and no new simulation is created in it. [R1 Q17 Ruan] (P-12)

### 5.4 Verification and reopening

- RN-25 Third party verification is optional and happens after finalizing; only a client making a claim goes through it. [R1 J5 Paulo, Ruan] [R1 J1 Paulo] [R1 J2 Ruan]
- RN-26 When the auditor asks for corrections, the project reopens for Peterson and the client, who fix it and send it again. [R1 J6 Paulo, Ruan] [R1 Q4 Paulo] [R1 Q12 Paulo]
- RN-27 When the auditor approves, the project is verified: its data stay locked and it never reopens. [R1 Q4 Paulo] [R1 Q16 Paulo]
- RN-28 The platform shows the state "verificado", with who verified and when. [R1 Q20 Paulo]
- RN-29 Reopening a project always takes a written reason. [R1 Q22 Paulo, Ruan]
- RN-30 Only GAIA reopens a finalized project that was not verified, and the PDF and QR code issued before stop being valid. [R1 Q15 Paulo] [R1 Q16 Ruan] (P-3)

### 5.5 Who acts

- RN-31 The project admin and the manager mark and change the official calculation. [R1 Q21 Paulo, Ruan] (P-9)
- RN-32 The project admin and the manager finalize the project. [R1 Q15 Paulo, Ruan] (P-2)

## 6. States

```
em andamento ──finalizar (admin, gerente)──► finalizado (travado)
     ▲                                         │            │
     └──── reabrir com justificativa (GAIA) ───┘            │ enviar para verificação (admin, gerente)
                                                            ▼
                       devolvido ◄──pede correção (auditor)── em verificação
                          │                                        │
                          └──corrige e reenvia (admin, gerente)──► │ aprova (auditor)
                                                                   ▼
                                                              verificado (nunca reabre)
```

While `devolvido`, the project is open for correction (RN-26). Whether `finalizado` without verification locks at all is P-1.

| State | Who sees | Who acts |
|---|---|---|
| em andamento | everyone with access to the project | admin, manager, technician fill and simulate; admin and manager mark official and finalize |
| finalizado | everyone with access | admin and manager send to verification; GAIA reopens |
| em verificação | everyone with access, the auditor | the auditor asks for corrections or approves |
| devolvido | everyone with access, the auditor | admin, manager, technician correct; admin and manager send again |
| verificado | everyone with access, the auditor | nobody changes data |

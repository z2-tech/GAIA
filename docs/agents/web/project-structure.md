# Project Structure

> Where new code goes. Read before adding a folder or wiring a new module. AI agents (Claude Code) should treat this as the source of truth, with `CLAUDE.md` for runtime and style rules.

## High-level layout

```
messages/            # i18n — pt.json and en.json
src/
├── app/             # Next.js App Router routes (thin shells only)
├── client/          # AUTO-GENERATED by hey-api/openapi-ts — never edit
├── components/      # Shared UI across features
│   ├── ui/          # Radix primitives + Tailwind (shadcn pattern)
│   ├── form/        # RHF-aware field components
│   ├── table/       # TanStack Table components
│   └── layout/      # PageTemplate, sidebar, header, footer
├── enums/           # Domain enum constants
├── features/        # All business logic and UI — organized by domain
├── hooks/           # Shared hooks (e.g. use-mobile.ts)
├── i18n/            # next-intl configuration
├── lib/             # Global infra
│   ├── api/         # HTTP client config, auth cookies, JWT refresh
│   ├── format/      # Date/number/string formatters
│   ├── geo/         # KML parser, GeoJSON types
│   ├── i18n/        # Locale cookie helpers
│   ├── errorHandlers.ts
│   ├── masks.ts     # Brazilian locale number helpers
│   └── utils.ts     # cn() helper
├── providers/       # Jotai, QueryClient, Toaster provider tree
├── schemas/         # Shared Zod schemas (if cross-feature)
├── services/        # TanStack Query wrappers over generated SDK
└── utils/           # Shared utility functions
```

## Three-layer rule

```
src/app/       ← Pages: thin shell. useParams + useTranslations + one feature import.
src/features/  ← All logic, hooks, components, schemas, types.
src/services/  ← TanStack Query wrappers. No business logic.
src/client/    ← Auto-generated. Never touch.
```

Pages import from `features/`. Features import from `services/`. Services import from `client/`.  
**Never call the SDK from a page or feature** — wrap in `services/`. `import type` of
DTOs is for domain mappers (`.ts`); `.tsx` consumes UI models.

### Unidirectional dependency flow

```
shared (components, lib, hooks)  →  services  →  features  →  app
```

## Feature module shape

Each feature lives at `src/features/<domain>/` and is **flat** — no nested features.

Folder names are **English** (see [`naming-conventions.md`](naming-conventions.md)):

```
src/features/<domain>/
├── module/
│   ├── components/    # Feature-scoped UI
│   ├── hooks/         # use-<domain>-module.ts — form state, mutations, submit logic
│   ├── lib/           # Pure helpers (no React)
│   ├── schemas/       # Zod schema factories + mappers
│   └── types/         # Explicit TS types (if complex)
├── dashboard/
│   └── dashboard.tsx
└── <domain>-page.tsx  # or index.tsx
```

Target examples (English):

- `src/features/carbon-removal/module/` — hooks, schemas, lib, components
- `src/features/regenerative/module/` — same pattern
- `src/features/farm/` — layout, header, tab menu types

> (`carbono-remocao`, `fazenda`, `modulo/`, `[projetoId]`). Renaming to English is
> tracked as a migration task; new code follows the English rule from the start.

## Navigation layer (`src/app/`)

Next.js App Router. Route groups in parentheses share layouts without URL segments.
Route segments are **English** (target below; current code still Portuguese).

```
src/app/
├── (auth)/login/        # Public auth route
└── (private)/           # All authenticated routes — layout handles session guard
    ├── (dashboard)/     # Home dashboard
    ├── profile/         # User profile
    ├── users/           # Admin: user management
    └── projects/[projectId]/farm/[farmId]/
        ├── general-data/
        ├── carbon-removal/      # index page + module/ subpage
        ├── carbon-emission/
        ├── regenerative/
        └── biodiversity/
```

Routes are thin shells: `useParams`, `useTranslations`, one feature component import.

## Services layer (`src/services/`)

One folder per backend domain. Reads in `<domain>.query.ts`, writes in `<domain>.mutation.ts`. Current domains:

```
auth · farms · lca · profile · projects · regenerative · roth-c · uploads · users
```

Adding a new query for an existing domain → add to the existing `*.query.ts`. New domain → create `src/services/<domain>/`.

## Generated client (`src/client/`)

`openapi-ts` outputs three files that matter:

- `sdk.gen.ts` — raw async functions for non-hook calls
- `@tanstack/react-query.gen.ts` — `*Options` and `*Mutation` factories (queryKey, queryFn, mutationFn)
- `types.gen.ts` — all request and response types

Regenerate after backend schema changes:

```bash
bunx @hey-api/openapi-ts
```

Config in `openapi-ts.config.ts`. **Never hand-edit `src/client/`** — the PreToolUse hook blocks it.

## Conventions

- **No barrel files.** Import the specific file (`import { Foo } from "@/features/foo/components/foo.tsx"`), not an `index.ts` re-export.
- **Features stay flat.** Subdivide internally with subfolders (`module/`, `dashboard/`), not with nested feature directories.
- **Compose at the app layer.** When two features need to interact, the route in `src/app/` orchestrates them.
- **Shared code lives at `src/components/`, `src/lib/`, `src/hooks/`.** If something inside a feature is needed by another feature, move it up before adding the second consumer.
